ABLATION RUN SETTINGS — abl_no_saf (row 7)  [leave-one-out]
================================================================
Study    : VnPollenBee ablation (abiliation/study_specifications.md)
Purpose  : Full model MINUS SAF-SIoU. Leave-one-out row — isolates
           SAF-SIoU's MARGINAL contribution on top of CBAM + BoT +
           VFL-w. Leave-one-in (row 3, abl_saf) showed SAF alone was
           +0.008 AP over baseline (below the noise floor) with the
           cleanest profile of rows 1-4 (best test AP 0.716); this row
           asks the harder question the leave-one-in cannot: does
           SAF-SIoU still add anything once CBAM/BoT/VFL are already
           present? If AP is unchanged vs abl_full, SAF-SIoU is
           redundant in the full stack and the final model can revert
           to the stock CIoU box loss.
Branch   : run/abl_no_saf  (branched from run/abl_full — same network,
           one factor removed)

COMPONENTS (protocol §2/§3) — SAF-SIoU OFF, other three ON
----------------------------------------------------------------
CBAM      : ON    (POLLENBEES_ATTN=cbam_botnet — CBAM on P3/P4/P5 maps)
BoT       : ON    (POLLENBEES_ATTN=cbam_botnet — P5 C2f -> BoTNet MHSA)
SAF-SIoU  : OFF   (box_loss_type: ciou — stock CIoU box regression)
VFL-w     : ON    (cls_loss_type: vfl, cls_pos_weight: [1.0, 2.0])

Config delta vs abl_full (row 9) — EXACTLY ONE factor:
  env var : POLLENBEES_ATTN cbam_botnet   (UNCHANGED — CBAM+BoT stay on)
  utils/args.yaml : box_loss_type saf_siou -> ciou   (drop SAF-SIoU)
    (saf_* params remain in the file but are inert while box=ciou)
This is a valid one-factor leave-one-out: only the box loss changes.

Architecture note: UNLIKE abl_no_cbam / abl_no_bot (which drop a factor
via the POLLENBEES_ATTN env and so change the NETWORK), this row changes
ONLY the loss. The network is therefore byte-identical to abl_full
(CBAM+BoT, cbam_botnet) — same modules, same parameter count. The sole
difference from abl_full is CIoU instead of SAF-SIoU for box regression.
There is no leave-one-in loss-only sibling to match against; the
comparison that matters is directly against abl_full.
